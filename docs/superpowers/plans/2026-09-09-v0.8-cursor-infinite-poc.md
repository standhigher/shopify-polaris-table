# 0.8 Cursor Infinite Loading POC

> 状态：实现完成，真实环境验收中。此 POC 不构成公共 API 或发布承诺。

## 目标与范围

验证 cursor 驱动的“加载更多”状态机能在不接触 V1 offset `TableQuery` 的前提下处理重复项目、终止条件与失败重试。实现位于 `src/experimental/CursorInfinitePOC.tsx`，不从包入口导出；它只复用既有的 V3 `CursorTableQuery`、`CursorDataPage`、`appendCursorPage` 和 `canLoadMoreCursorPage`。

| 项目 | POC 决策 |
| --- | --- |
| 查询 | 每次请求显式传递 `{mode: 'cursor', pageSize, cursor}`；不接受或生成 `page` / `offset` |
| 合并 | 以调用方提供的稳定 ID 去重；后到的重复项目不会替换已显示项目 |
| 终止 | `nextCursor: null` 时移除加载控件并用 `status` 宣告完成 |
| 失败 | 保留当前 cursor 和已加载项目；错误以 `alert` 呈现，重试使用同一 cursor |
| 无障碍 | 请求中和终止时使用 `role=status` / `aria-live=polite`；错误使用 `role=alert` |
| V1 隔离 | 不导出组件、不修改 `Table`、不引入 URL/offset pagination 或 Admin 状态 |

## 验收指标

- React 测试验证 V3 cursor 请求不含 `page`，跨页重复 ID 只显示一次。
- React 测试验证加载中状态、`nextCursor: null` 的终止状态，以及失败后用相同 cursor 重试。
- Storybook 手动检查窄容器中加载按钮、读屏状态和错误重试；还需在真实 Extension 容器记录请求取消、重复点击与网络失败体验。
- 若宿主无法保证 cursor 的稳定排序、重试造成重复写入、读屏状态重复播报，或需和 V1 offset 同一查询对象混用，则不提升为公开 API。

## 当前验证记录

- **单元/React 测试：** 覆盖去重、V3 query 隔离、加载/无更多，以及失败恢复。
- **Chrome 本地 Storybook：通过基础加载冒烟。** 连续加载两个 mock cursor page 后，重复的 Third row 仅保留一次，最终显示 All rows loaded。
- **待验证：** Safari、真实嵌入容器、VoiceOver/NVDA 朗读、慢网/取消请求，以及服务端 cursor 在数据变更中的稳定排序。

## 已知限制与回滚

该 POC 不处理 initial fetch、刷新、取消进行中请求、双向滚动、虚拟化、缓存、选择或行内编辑。它不代表服务端 cursor 契约的实现。回滚仅需删除 `src/experimental/CursorInfinitePOC.tsx`、测试与 Storybook 场景；V1 `Table` 和既有公开 V3 helper 不受影响。
