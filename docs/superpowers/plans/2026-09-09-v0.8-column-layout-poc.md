# 0.8 Column Resize / Reorder POC

> 状态：实现完成，真实环境验收中。此 POC 不构成公共 API、持久化格式或发布承诺。

## 目标与范围

验证一个独立 renderer 是否能在**受控**布局状态下安全完成有限的列宽调整和顺序调整。实现位于 `src/experimental/ColumnLayoutPOC.tsx`，不从包入口导出；状态变换复用 `src/v3/columns.ts` 中的 `resizeColumn` 与 `reorderColumns`。

| 项目 | POC 决策 |
| --- | --- |
| 状态所有权 | 调用方传入 `ColumnLayoutState` 并处理 `onLayoutChange`；组件不保存布局状态 |
| 调整宽度 | 每列使用键盘可访问的 range 控件；由 `minWidth` / `maxWidth` 约束 |
| 调整顺序 | 显式左右按钮，或聚焦 column header 后按 `Alt+ArrowLeft` / `Alt+ArrowRight` |
| 拖拽 | 不实现；不以 POC 推断 drag-and-drop、触屏或 pointer capture 可行性 |
| 列可见性 | 仅遵从传入 layout 的 `visible` 状态；不提供切换 UI |
| 兼容性 | 不接入 V1 `Table`、sticky、虚拟滚动、sorting、selection、inline edit 或 popover |

## 验收指标

- React 测试验证受控 resize 的 min/max 边界、顺序变更以及可通过键盘触发的重排。
- Storybook 可检查窄宽横向滚动、tab 焦点、range 控件和顺序变化后的单元格对齐。
- 在 Chrome、Safari 和真实嵌入容器中补测 resize 的焦点 ring、最小触控尺寸、缩放、RTL 和与 sticky header/column 的交互。
- 如控制状态与实际列定义不同步、焦点丢失或持久化数据错误应用到错误列，则维持内部 POC，不接入 V1 `Table`。

## 持久化与失效风险

当前组件**不持久化** layout。若后续宿主持久化 `ColumnLayoutState`，必须把数据 schema/version、表标识、用户/店铺范围以及稳定的 column id 纳入 key。列 id 重命名、列移除、权限导致的隐藏、`minWidth`/`maxWidth` 收紧和新列插入都可能使旧偏好失效。恢复时必须以当前列定义为权威：丢弃未知 id、补入新列、重新 clamp 宽度，并避免跨表或跨权限范围复用。

## 当前验证记录

- React 单元测试覆盖受控宽度调整、边界属性和 `Alt+ArrowLeft` 重排。
- **Chrome 本地 Storybook：通过基础受控重排冒烟。** 在窄浏览器视口中，点击 Customer 的右移控制后表头顺序更新为 Status、Customer、Total；组件仍以调用方 layout 为唯一状态来源。
- **待验证：** Safari、真实嵌入容器、RTL、缩放、触屏、sticky/virtual renderer 组合，以及辅助技术对 header 内多个控件的朗读顺序。

## 已知限制与回滚

不实现拖拽重排、自动宽度、列固定、持久化、数据迁移、动态列权限、动态行高、row action、selection、sorting、popover 或 V1 兼容性。若 POC 验收失败，删除 `src/experimental/ColumnLayoutPOC.tsx`、对应测试与 Storybook 场景即可；`src/v3/columns.ts` 和公开 API 均不需回滚。
