# 0.8 Sticky Header / Column POC

> 状态：进行中。此 POC 不构成公共 API 或发布承诺。

## 目标与范围

验证固定列宽的独立 table renderer 能否在水平与垂直滚动中保持顶部 header、起始固定列与结束固定列的层级正确。实现位于 `src/experimental/StickyTablePOC.tsx`，不从包入口导出，并复用现有 `getStickyOffsets` 的布局计算。

| 项目 | POC 决策 |
| --- | --- |
| 列宽 | 调用方提供固定像素宽度；resize 与自动布局不在范围内 |
| 滚动 | 单一 `overflow: auto` 容器，同时验证横向与纵向滚动 |
| 堆叠 | 普通固定单元格 z-index 2；顶部 header 3；顶部与固定列交叉单元格 4 |
| 焦点 | 滚动区域本身可聚焦；不提供单元格操作或 roving focus |
| Polaris | 不接入 `IndexTable`，不验证 popover、选择、排序或 bulk action |
| 兼容性 | Chrome、Safari、窄屏和宿主 shadow/stacking context 必须实测 |

## 验收指标

- 测试固定列的 start/end offset、header 堆叠层级和横向滚动容器。
- Storybook 在窄宽下检查左右固定列不会遮盖中间单元格；垂直滚动后 header 仍在顶部。
- 在 Safari、Chrome 和目标嵌入容器检查 `position: sticky`、z-index、focus ring、popover 裁剪与 RTL inset 行为。
- 如出现 Safari sticky 失效、焦点被遮挡、行选择/排序或浮层无法兼容，则保持内部 POC，不修改 V1 `Table`。

## 当前验证记录

- **Chrome 本地 Storybook（320px 宽）：通过基础滚动、堆叠与焦点检查。** 横向和纵向各滚动 400px 后，header 的 top 仍与滚动区 top 对齐；起始固定列保持在左侧，结束固定列保持在右侧，中间列随横向滚动移出视区；滚动区可获得键盘焦点。
- **待验证：** Safari、真实嵌入容器、RTL、popover 裁剪，以及与 V1 selection/sorting 的兼容性。当前 POC 不集成这些交互。

## 已知限制与回滚

不实现 auto-width、resize、reorder、动态行高、虚拟滚动、row action、selection、sorting、popover 或 RTL 专项行为。回滚只需删除 `src/experimental/StickyTablePOC.tsx` 与 Storybook 场景；公开的 V3 column-layout helper 和 V1 `Table` 不受影响。
