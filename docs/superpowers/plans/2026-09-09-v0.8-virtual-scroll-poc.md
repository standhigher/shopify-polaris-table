# 0.8 Virtual Scrolling POC

> 状态：进行中。此 POC 不构成公共 API 或发布承诺。

## 目标与范围

验证固定行高、非交互列表能否在不改变 V1 `Table` 的前提下，仅挂载可见窗口及少量 overscan 行。实现位于 `src/experimental/VirtualListPOC.tsx`，不从包入口导出；它复用框架无关的 `calculateVirtualWindow`，不耦合 Polaris `IndexTable`。

| 项目 | POC 决策 |
| --- | --- |
| 数据量 | 10,000 行固定行高样本 |
| 行高 | 调用方显式传入；动态高度不在范围内 |
| 窗口 | 可见行 + 默认 2 行 overscan |
| 焦点 | 仅滚动容器可聚焦；不提供 roving focus 或行内控件 |
| 读屏 | `list` / `listitem` 语义和实时窗口状态；不宣称等同原生表格导航 |
| Polaris | 不接入 `IndexTable`，避免尚未验证的 selection、sorting 与 sticky 兼容性 |
| 服务端 | 不处理请求、cursor、分页、选择或持久化 |

## 验收指标

- 单元/React 测试验证 10,000 行时只渲染 bounded window，并在滚动后替换窗口。
- Storybook 手动检查 320px 高容器的滚动、Tab 焦点可见性，以及 VoiceOver/NVDA 对 list 语义的朗读。
- 在 Safari、Chrome 和目标嵌入容器中记录首屏与连续滚动性能；目标为不出现长任务或明显掉帧，最终数值应由真实容器采集。
- 若任一浏览器中出现焦点丢失、读屏顺序错误、动态高度重叠或与 Polaris 行选择不兼容，则保持为内部 POC，不接入公共 `Table`。

## 当前验证记录

- **Chrome 本地 Storybook（320px 宽）：通过基础布局与焦点检查。** 滚动容器 `scrollWidth` 与 `clientWidth` 均为 256px；滚动到 640px 后渲染窗口从首批项目切换至第 19–32 行，页面仍仅挂载 14 个 listitem；容器可获得键盘焦点。
- **Chrome 本地 Storybook（压力冒烟）：通过窗口上限检查。** 连续 20 次、每次 640px 滚动后，位置为 12,800px，仍只挂载 14 个 listitem；页面 DOM 节点数由 121 到 139，未出现随 10,000 行数据无界增长的迹象。当前自动化浏览器不提供 Long Tasks Performance API，不能据此得出帧率或长任务性能结论。
- **人工本地验收：总体符合预期。** 已由项目方在本地 Storybook 场景确认；该结论不替代 Safari、真实嵌入容器或辅助技术的专项验收。
- **Safari 本地 Storybook：通过核心窗口与焦点检查。** 10,000 行初始仅挂载 12 行；滚动至 12,800px 后为第 399–412 行且只挂载 14 行；列表容器可获得焦点。
- **待验证：** 真实嵌入容器、VoiceOver/NVDA 朗读顺序，以及带性能面板的连续滚动长任务与掉帧数据。

## 已知限制与回滚

动态行高、可编辑单元格、行操作、行选择、sticky 列、分组、拖拽和复杂焦点恢复均未实现。回滚方案是删除 `src/experimental/VirtualListPOC.tsx` 与对应 Storybook 示例；V1 `Table` 和已经发布的 V3 window helper 不受影响。
